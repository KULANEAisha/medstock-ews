# Medicine Stockout Early-Warning Assistant

Which facilities are about to run out of essential medicines, and where could stock be moved from? Ask in plain English and get an answer built from real calculations, not guesses.

> **All data is synthetic.** It was generated by `medstock/data_gen.py`. The facilities, districts and stock figures are invented. Nothing here describes a real health facility.

## What it does

- **Risk table:** facilities by medicine, colour-coded by how many months of stock are left.
- **Stock card:** click any cell to see the history and exactly how its status was worked out.
- **Assistant:** ask things a table can't answer, such as *"Where can F10 get amoxicillin from, and how much?"* Every answer shows the calculations it used.

## How it works

**Forecast.** Months of stock = stock on hand ÷ average monthly use over the last 3 months. Simple on purpose, so anyone can check it by hand.

| Status | Months of stock |
|---|---|
| Stockout risk | under 1 |
| Watch | 1 to 2 |
| OK | 2 to 6 |
| Surplus | over 6 |

**Redistribution.** Surplus facilities keep 3 months of stock and can send the rest to nearby at-risk facilities (default limit 60 km). Anything that can't be covered is reported as unmet need. These are suggestions for a person to review.

**Assistant.** Gemini (`gemini-3.5-flash-lite`, free tier) can only answer by calling four tools: `get_catalog`, `get_facility_stock`, `get_at_risk_facilities`, `suggest_redistribution`. It is told to use only their results and to say so when data is missing. Unknown facilities, medicines or districts return "no data", never an estimate.

**Stack.** Python and pandas, FastAPI backend (Render), React front end (Netlify).

## Limitations

- Synthetic data only. Real data would be late, incomplete and messy.
- Demand is underestimated during a stockout, because a facility can't dispense stock it doesn't have.
- No expiry dates, lead times or orders already on the way. "Surplus" means a lot of stock, not stock about to expire.
- Distance is in a straight line, not road travel.
- Free hosting is slow to wake, and the chat has no login.

## With real data, I would

- Agree data access and privacy rules first, and show data quality in the interface.
- Test forecasting methods on held-out months and report the error.
- Keep a named person approving every redistribution, and log the outcome.
- Re-run the evaluation whenever the model, prompt or tools change, using questions written by someone other than me.

## Run it locally

Needs Python 3.11+ and Node.js. Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest -q

$env:GOOGLE_API_KEY = "your-key"
$env:GEMINI_MODEL = "gemini-3.5-flash-lite"
uvicorn medstock.api:app --reload
```

In a second terminal:

```powershell
cd frontend
copy .env.example .env.local
npm install
npm run dev
```

Open http://localhost:5173. Run the evaluation with `python -m evaluation.run_eval --no-cache --delay 15`.
